# 給 Claude：第一版免登入收藏的設計與審閱說明

使用者已同意第一版採免登入收藏，並要求先開 PR。這是獨立的小功能，與 2028–2030 長遠願景分開，不代表整體改版、會員或通知功能已啟動。

## 為什麼先這樣做

目前網站已有型號行情與文章篩選。重複查同一機型的人，每次回來都要重新找條件；第一版要解決的是這個重複操作。

收藏只用瀏覽器 localStorage，就能在既有 GitHub Pages 架構中完成，不需新增帳號、密碼、寄信服務或後端資料庫。先提供立即有用的功能，再看使用者是否真的需要跨裝置同步，符合按部就班的方向。這是範圍選擇，不是對未來會員功能的否定，也不是已證實的流量成效。

## 收藏的是什麼

- 型號行情的收藏按鈕保存精確 `model + storage`，再次點擊可取消。
- 文章區可收藏目前 `model + storage + status + q` 條件；可以只收藏搜尋文字或文章狀態。
- 不保存文章正文、價格快照或售出判斷。每次開啟頁面，符合篇數與文章都由這次載入的 `data.json` 重新算出；資料新鮮度仍以頁首最後回訪時間為準。
- 查看收藏會完整還原條件、把文章分頁重設為第一批，並移到文章區。精確機型限制會明示，且可清除。
- 找不到符合資料時仍保留收藏，讓使用者自行移除。符合篇數不等於型號行情的刊登數：後者目前只納入有價格的文章。

型號與容量採精確比對，例如 `iPhone 16 Pro` 不會混入 `Pro Max`。`null` 代表不限；容量空字串代表原始資料容量未提供，不能擴大解釋為不限容量。

## 使用者會知道的限制

介面明示免登入、只在這個瀏覽器保存、不跨裝置同步、清除網站資料後消失，以及不會發送通知。換瀏覽器、換裝置或未來換網域不會自動帶走收藏；這版也沒有匯入、匯出或雲端備份。

瀏覽器拒絕讀取／寫入（例如儲存空間不足）時，保留當頁暫存並顯示提示，不顯示成已永久保存。重新整理後可能消失。

## 實作界線

- `site/watchlist.js`：小型無依賴模組；使用專案專屬 key `ptt-iphone-tracker:watchlist:v1`，避免同一 GitHub Pages 網域下其他專案混用。
- 儲存格式為 `{version: 1, items: [...]}`，每筆只留上述四個欄位；驗證字串、狀態、長度與上限 30 組，搜尋大小寫與多餘空白正規化去重。
- 異常舊資料不在載入時寫回或覆蓋，先顯示提示；使用者再次收藏時才保存有效清單。
- 收到同來源的 localStorage 變更事件時同步清單；新增／移除前再讀一次，降低舊分頁蓋掉新收藏的機率。這不是跨裝置同步，也不保證兩個分頁同時寫入的原子性。
- 收藏標籤與條件插入 HTML 時轉義，儲存不受信任內容也不能當成 HTML 執行。
- 不改爬蟲、資料 CSV、時間語意、統計方法、排程或正式部署。`build_site.py` 只增加新 JavaScript 的複製項目。

## 審閱重點

1. 原有日期切換、動態、行情排序及文章分頁仍正常。
2. 重新整理、重複收藏、取消、移除和精確條件還原正確。
3. 容量未提供、暫時沒有符合資料、異常儲存與拒絕儲存有清楚處理。
4. 手機上可直接找到型號收藏操作；鍵盤焦點不因表格更新遺失。
5. 價格仍是既有刊登／已售標價口徑，本 PR 不新增成交推論。

## 驗證方式

- `python -m unittest`：依 AGENTS.md 執行既有離線測試；建置測試涵蓋靜態檔案複製。
- `node --test tests/watchlist.test.cjs`：用 Node 內建測試涵蓋持久化、去重、條件邊界、格式驗證、錯誤降級及分頁間重讀。
- 瀏覽器操作另外檢查手機／桌面、儲存與移除、重新載入、資料更新、精確匹配、拒絕儲存及跨分頁。實際結果記在 PR。
