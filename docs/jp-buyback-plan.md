# 日本買取價頁上線計畫（草案，2026-10-07）

在「PTT MacShop交易觀測」同一個網站下多一頁 `jp/`，比較日本多家買取店收購 iPhone 18 Pro 系列的價格與走勢。PTT 頁看「台灣二手賣多少」，這頁看「日本店家收多少」。

## 1. 先講結論：三家來源實測結果

2026-10-07 用暫時的 GitHub Actions job（和現在爬 PTT 同一種雲端主機、同樣用 curl_cffi 模擬瀏覽器）實際抓過：

| 來源 | Actions 抓得到嗎 | 說明 |
|---|---|---|
| mobile-mix.jp `?category=7` | **可以**（200） | 靜態 HTML，一頁就有全部 iPhone。 |
| pastec.net（モバステ） | **不行**（403） | AWS 防火牆直接擋雲端 IP；chrome／safari／firefox 五種指紋都 403，連 robots.txt 都拿不到。另外你給的 `blog/info33376` 是文章，不是價格表；價格表在 `pastec.net/iphone`。 |
| suruga-ya.jp `kaitori/search_buy` | **不行**（403） | Cloudflare「Just a moment...」驗證頁，五種指紋都過不了。 |

這兩家是刻意擋自動程式，**計畫不去繞過**（不用代理 IP、不破驗證頁）。所以起步改成：

- **mobile-mix**（你指定的，抓得到）
- **イオシス買取** `k-tai-iosys.com/pricelist/smartphone/iphone/iphone18-pro/`（替補，Actions 實測 200，robots.txt 允許但要求每次間隔 60 秒）
- **アメモバ買取** `amemoba.com/smartphone/iphone/iphone-18-pro/`（替補，Actions 實測 200，robots.txt 全部允許）

pastec、駿河屋留在「待加入」：程式做成一家一個模組，之後若找到可行方式（例如對方提供資料、或改從非雲端主機抓）再補上。這點需要你決定，見最後一節。

## 2. 各站資料長相（實測）

**mobile-mix**（`https://mobile-mix.jp/?category=7`，頁首「更新日：2026/10/07」）
- 每個商品是 `table.list` 裡的 `<tr id="613">`：`td.product` 型號＋容量（「iPhone 18 Pro Max 256GB」），`td.price`（「245,000円」）。
- 下一列 `td.open` 是狀態（「未開封」），旁邊一格是顏色減價文字（「グレイシャー/ブラック-20,000円､シルバー-24,000円」）。
- 表單裡 `input.colorCircle` 的 `value` 直接是各色減價（`0`、`-20000`、`-24000`），可以精確算出每個顏色的價格。
- 「シルバー買取不可」「バーガンディのみ 他色買取不可」這類字樣代表該色不收。
- 這一頁只有未開封；另有「Apple(iPhone開封済)」分頁是用表單切換，第一階段不做。
- 10/07 實測 18 Pro／Pro Max 都只有 256GB、512GB、1TB，沒有 2TB。

**イオシス**（每個型號一頁：`.../iphone18-pro/`，Pro Max 推測為 `.../iphone18-pro-max/`）
- 依「docomo版／au版／SoftBank版／国内版 SIMフリー」分組，每格有「未使用品買取価格」與「中古買取価格 ～」。
- 實測各電信版同價（256GB 未使用 192,000円）；欄位的 HTML class 尚未記錄，交給實作時看。

**アメモバ**（`.../iphone-18-pro/`，Pro Max 推測為 `.../iphone-18pro-max/`）
- 頁首有更新日（「2026年10月05日」）；依「国内版SIMフリー／au版／docomo版／SoftBank版」分組，「未開封買取価格」或「新品買取価格」＋「中古買取価格 円〜」。
- 實測 SIMフリー 比電信版高（256GB 200,000 vs 192,000），所以電信版要分開記。

**同一天三家比較（10/07 實測，未開封、日圓；イオシス為電信版 SIMフリー，該站各版同價；アメモバ為国内版 SIMフリー）**

| | mobile-mix | イオシス | アメモバ |
|---|---|---|---|
| 18 Pro 256GB | 212,000 | 192,000 | 200,000 |
| 18 Pro 512GB | 244,000 | 223,000 | 225,000 |
| 18 Pro 1TB | 308,000（限バーガンディ） | 285,000 | 290,000 |

同規格差到 2 萬日圓，這就是多家比較的價值。

## 3. 範圍（第一階段）

- 機型：iPhone 18 Pro、iPhone 18 Pro Max。
- 容量：各站實際有的（256GB／512GB／1TB／2TB）。
- 狀態：統一成兩種
  - `未開封`（mobile-mix「未開封」、イオシス「未使用品」、アメモバ「未開封／新品」）——頁面主角，三家都有。
  - `中古上限`（「中古買取価格」那個數字，代表狀態最好的中古收價）——先存起來，頁面只當補充。
- 版本：`SIMフリー` 為主；電信版另存，頁面預設只顯示 SIMフリー。mobile-mix 沒寫版本，視為 SIMフリー。
- 顏色：主價格用各站標的價格（最高色）。mobile-mix 有精確顏色減價時另存每色價格；其他站第一階段不分色。

## 4. 資料設計（`data/jp/`，和 PTT 的 `data/` 完全分開）

- `data/jp/prices.csv`：**價格歷史，只附加不改寫**。一個規格（店×機型×容量×狀態×版本×顏色）價格有變才新增一列，所以走勢圖用「階梯線」畫。
  欄位：`shop, model, storage, condition, carrier, color, price_jpy, observed_at, shop_updated, source_url`
  - `observed_at`：第一次抓到這個價格的時間（`+09:00` ISO 8601，日本時間）。
  - `shop_updated`：店家頁面寫的更新日（沒有就空白）。
  - `price_jpy` 空白＝這次頁面上這個規格不見了（下架／不收）。
- `data/jp/latest.csv`：每次整檔覆寫，目前每個規格的價格與 `last_checked`，網頁的比較表用它。
- `data/jp/runs.csv`：每次執行每家一列（`run_at, shop, status, rows, error`），只附加。某家連續失敗、或抓到 0 筆就看得出來是改版。
- 估計量：三家約 60 個規格，價格每天變一兩次，一年幾萬列，CSV 夠用。

## 5. 爬法與排程

- 新程式 `jp/buyback.py`（不碰 `tracker.py`）：每家一個 `parse_<shop>(html) -> list[dict]` 純函式，抓取共用 `fetch`（curl_cffi impersonate），每個請求間隔至少 5 秒，イオシス 60 秒。
- 新 workflow `.github/workflows/jp.yml`：**預設每 6 小時**（日本時間 03:30／09:30／15:30／21:30，錯開 PTT 的排程），commit `data/jp/` 回 main 後觸發 `pages.yml`。推送沿用 track.yml 的「rebase 後重試三次」。
- 解析防呆：某家這次 0 筆或比上次少一半以上，視為改版／被擋，不寫 `prices.csv`，只在 `runs.csv` 記失敗，避免把整排價格記成「下架」。
- 測試：把三家實際頁面精簡後放 `tests/fixtures/jp/`，離線測解析；`python -m unittest` 照舊全過。

## 6. 頁面（`site/jp/index.html`）

參考的 iphone-buyback-tracker.pages.dev 只追一家店的未開封價格與顏色／容量走勢。這頁的差異：

1. **最高買取價比較表**（首屏）：列＝機型×容量，欄＝各店未開封價，最高的標出來，另一欄寫「最高 vs 最低差多少」與各店更新時間。手機上改成每個規格一張卡片。
2. **價格走勢**：選機型＋容量，每家一條階梯線，可切 7 天／30 天／全部；另一條粗線是「當下最高價」。
3. **今日變動**：比昨天漲跌最多的規格（各店）。
4. **mobile-mix 顏色減價**：該店有精確色價時，在比較表的格子裡小字列出。
5. 每格都連回店家原頁；頁尾註明「價格以店家頁面為準，可能有數量、顏色、版本、付屬品等條件」。

顯示規則：
- **只顯示日圓**（`¥245,000`）。不換算台幣：匯率要另找來源、又會讓人誤以為是台灣價格。之後想做「日本收購價 vs PTT 二手價」再加台幣參考（第三階段）。
- 介面用繁體中文，店名與日文規格照原文。
- 異常值：某店價格比其他店中位數低一半或高一倍，比照 PTT 的規則先不公開。

## 9. 風險

- **被擋**：pastec、駿河屋已確認擋雲端 IP；其他三家將來也可能擋。`runs.csv` 會看出來，屆時再評估。
- **改版**：店家改 HTML 就會抓不到；防呆會停寫並留紀錄，修解析即可，歷史資料不受影響。
- **條件價**：買取價常有「限某色」「數量上限」「需會員」「期間限定」等條件。mobile-mix 的條件文字原樣存在顏色欄說明；頁面一律寫「最高可收價，實際依店家條件」。
- **條款**：mobile-mix 利用規約的禁止事項沒有提到自動取得；イオシス、アメモバ robots.txt 允許。駿河屋 robots.txt 沒擋 `/kaitori`、要求間隔 30 秒，但實際用 Cloudflare 擋。頻率維持每 6 小時一次、每站幾個請求，負擔很小。
- **時區**：日本資料一律存 `+09:00`，網頁顯示日本時間並標明「日本時間」，和 PTT 頁的台灣時間分開。
